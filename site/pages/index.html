Fossel is a local-first MCP memory server. It keeps your repo's conventions, bug fixes and decisions in SQLite on your machine, and serves them back to Claude Code, Cursor, Gemini CLI, OpenCode, Windsurf and any other stdio MCP client.

What it solves

Coding agents start every session knowing nothing about your repo. You re-explain the same conventions, and the agent re-makes the same mistakes. Fossel gives the agent somewhere to write that down and read it back.

  • You say remember: JWT lives in localStorage; 401 redirects to /login. Fossel stores it against the repo, infers a type and tags, and merges near-duplicates.
  • Later the agent calls get_context and gets the pinned, recent and matching memories for that repo.
  • Memories are scoped to the repo, resolved from its git remote (for example acme/storefront), so two projects do not mix.

Local-first, and what that covers

  • Storage: one SQLite file, ~/.fossel/memory.db by default. Set FOSSEL_DB_PATH to move it.
  • Search: SQLite FTS5, with an optional local hybrid mode. No model download and no embedding service by default.
  • Network at runtime: the server code imports no networking modules, so it does not call out. The one exception is the optional FOSSEL_EMBEDDER_CMD, a command you choose and run yourself.
  • First run with npx: npx downloads the package from npm the first time, so that step needs the network. A global install (below) removes it.

Quickstart

You need Node.js 20 or newer. Run the onboarding command inside a git repository:

npx -y fossel init

It prints the repo key Fossel resolved, the MCP config to paste into your client, and the database path. If the database is empty it adds one starter memory. If the repo has an AGENTS.md, CLAUDE.md or similar rule file, it appends a one-line hint telling the agent to call get_context at the start of a session.

Then add Fossel to your client. Each client has its own page:

  • Claude Code
  • Cursor
  • Gemini CLI
  • OpenCode & Windsurf

Every client launches the same server. The command it runs is:

npx -y fossel

With no arguments, fossel starts the MCP server on stdio. You do not normally run it by hand.

Use it from chat

Once your client has connected, say:

remember: Fossel is working in this repo

Then ask:

what does Fossel remember?

You should see the memory come back. To see which repo Fossel thinks you are in, ask the agent to call resolve_repo.

Install globally instead of using npx

A global install avoids the download on every cold start and works offline once installed.

npm install -g fossel fossel init

In your client config, use fossel as the command with no arguments, instead of npx with -y fossel.

Command line

CommandWhat it does
fosselStart the MCP server on stdio.
fossel init [--no-dedupe]Onboarding: resolve the repo, print the MCP config, merge legacy repo keys, auto-merge exact duplicates unless --no-dedupe is given.
fossel doctor [--fix]Report sibling repo keys, duplicate clusters and stale mentions. Without --fix it changes nothing and exits non-zero when it finds a problem, so it can run in CI. With --fix it applies the safe cleanups. It looks for Cursor and Claude Desktop config files only.
fossel statsRead-only summary for the current repo: live, superseded and pinned counts, memory types, stale and code-drift counts, top tags, database size.

Environment variables

VariablePurpose
FOSSEL_DB_PATHDatabase file. Default ~/.fossel/memory.db.
FOSSEL_WORKSPACEProject root used for repo detection. Falls back to the server's working directory. Set it when a client launches the server from the wrong folder.
FOSSEL_EMBEDDINGSSet to 1, true, on or yes to enable hybrid keyword and vector search.
FOSSEL_EMBEDDER_CMDCommand that embeds text, to use a stronger model than the built-in one. Optional.
