Claude Code adds MCP servers with claude mcp add. Fossel runs as a local stdio server.

Not tested here: Claude Code was not installed on the machine that wrote this page. The Claude Code side follows the Claude Code MCP docs. Fossel's side (the command, arguments and environment variables) is checked against the Fossel source.

Add Fossel

Run this inside your project:

claude mcp add fossel -- npx -y fossel

Everything after -- is the command Claude Code runs. Any claude options, such as --env or --scope, go before the server name.

Choose a scope

ScopeCommandWhere it applies
local (default)claude mcp add fossel -- npx -y fosselThis project, for you only. Stored in ~/.claude.json.
projectclaude mcp add --scope project fossel -- npx -y fosselWritten to .mcp.json in the project root, so teammates who clone the repo get it. Claude Code asks each person to approve it.
userclaude mcp add --scope user fossel -- npx -y fosselEvery project you open.

The file that project scope writes looks like this:

{ "mcpServers": { "fossel": { "type": "stdio", "command": "npx", "args": ["-y", "fossel"] } } }

Verify

  1. Check the server and its status: claude mcp get fossel, or claude mcp list for all servers.
  2. Start claude in your project and run /mcp to see the connection status.
  3. Ask Claude to call the resolve_repo tool. It returns the repo key Fossel is using, for example acme/storefront.
  4. Say remember: Fossel is working in this repo, then what does Fossel remember?

If it picks the wrong repo

Fossel decides the repo from FOSSEL_WORKSPACE, or else from the working directory the client starts it in. If resolve_repo shows the wrong key, pin the project root with an absolute path:

claude mcp add --env FOSSEL_WORKSPACE=/absolute/path/to/project fossel -- npx -y fossel

A fixed path only suits local or project scope. For user scope, leave it unset.

Remove

claude mcp remove fossel
