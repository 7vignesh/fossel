Fossel registers 17 tools and one resource. This page is generated from the running server: the parameter tables come from its tools/list response and every example is a request and response recorded by npm run docs:snapshot. A test fails if either drifts from the code.

Conventions

  • repo is optional on every tool that has it. Omit it to use the repo of the current workspace. See How Fossel Works for how a repo is resolved.
  • Ids. A memory has a numeric id, shown as (2) in listings, and a longer string id shown as legacy: …. Tools that take an id accept either. A superseded memory is not found by either.
  • Memory types are convention, bug_fix, reviewer_pattern, decision, issue and general.
  • Return format. Every tool returns one block of plain text. Most of that text is meant for the model to read, not for a program to parse. resolve_repo and export_memories return JSON text.
  • Errors. A failure inside a tool is returned with isError: true and a message, and does not end the session. A call with invalid arguments is rejected by the MCP layer before the tool runs, with a validation message that names the field.
  • Examples come from one scripted session on a throwaway database, so the ids and numbers in them are consistent from one example to the next. Timestamps in the session are fixed.
