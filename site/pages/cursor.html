Cursor reads MCP servers from an mcp.json file. Fossel runs as a local stdio server.

Not tested here: Cursor was not installed on the machine that wrote this page. The Cursor side follows the Cursor MCP docs. The JSON below is what npx -y fossel init prints, and Fossel's side is checked against the source.

Add Fossel

Cursor reads two files:

  • ~/.cursor/mcp.json applies to every project.
  • .cursor/mcp.json in a repository applies to that project and can be committed so teammates share it.

Create or merge this entry into mcpServers:

{ "mcpServers": { "fossel": { "command": "npx", "args": ["-y", "fossel"], "env": { "FOSSEL_WORKSPACE": "${workspaceFolder}" } } } }

FOSSEL_WORKSPACE pins Fossel to your project root. Cursor sometimes launches MCP servers from your home directory, which would file memories under the wrong repo. Cursor expands ${workspaceFolder} in this file.

Restart Cursor after editing the file.

Verify

  1. Open the MCP tools list in the chat panel and confirm fossel is listed and its tools are enabled.
  2. Ask the agent to call resolve_repo. The reply names the repo key, for example acme/storefront. If it names your home folder or the wrong project, the workspace setting did not apply.
  3. Say remember: Fossel is working in this repo, then what does Fossel remember?

By default Cursor asks for approval before an agent uses an MCP tool, so the first calls will prompt you.

npx fossel doctor checks that ~/.cursor/mcp.json exists. It does not read project-level .cursor/mcp.json files.
