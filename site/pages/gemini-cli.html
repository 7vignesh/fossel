Gemini CLI reads MCP servers from settings.json. Fossel runs as a local stdio server.

Not tested here: Gemini CLI was not installed on the machine that wrote this page. The Gemini CLI side follows the Gemini CLI MCP docs. Fossel's side is checked against the Fossel source.

Add Fossel

Add the server to one of these files:

  • ~/.gemini/settings.json for every project.
  • .gemini/settings.json in a repository for that project.
{ "mcpServers": { "fossel": { "command": "npx", "args": ["-y", "fossel"] } } }

Gemini CLI also has a gemini mcp add command. Its documented form is gemini mcp add [options] <name> <commandOrUrl> [args...], but its docs do not say how it treats an argument that starts with a dash, like the -y here. Editing settings.json avoids the question.

Verify

  1. Start gemini in your project and run /mcp. Fossel should be listed as connected, with its tools.
  2. Ask Gemini to call resolve_repo. The reply names the repo key.
  3. Say remember: Fossel is working in this repo, then what does Fossel remember?

If it picks the wrong repo

Fossel uses the working directory Gemini CLI starts it in. If resolve_repo shows the wrong key, add an env block with an absolute path:

{ "mcpServers": { "fossel": { "command": "npx", "args": ["-y", "fossel"], "env": { "FOSSEL_WORKSPACE": "/absolute/path/to/project" } } } }

Do not use Cursor's ${workspaceFolder} here. Gemini CLI expands environment variables from your shell inside env, not editor placeholders.

If the server does not show up

Gemini CLI can ignore a project's .gemini/settings.json in a folder it does not trust. If a project-level entry is missing from /mcp, trust the folder or move the entry to ~/.gemini/settings.json.
