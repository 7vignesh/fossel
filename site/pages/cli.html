Fossel has one binary, fossel. With no arguments it runs the MCP server. The other commands are for setup and upkeep, and they act on the repo in the current directory. Every output below was recorded from the real CLI by npm run docs:snapshot.

Commands

CommandWhat it does
fosselStart the MCP server on stdio. This is what an MCP client launches.
fossel init [--no-dedupe]Onboarding. Resolve the repo key, merge memories saved under older keys, remove exact duplicates (skip with --no-dedupe), add a starter memory if the whole database is empty, print the MCP config, and append a get_context hint to rule files that already exist.
fossel doctor [--fix]Check the repo's health. Without --fix it changes nothing and exits 1 if it finds a problem. With --fix it merges sibling keys, rewrites stale mentions and removes exact duplicates.
fossel statsPrint a read-only summary for the current repo.
fossel --help, -hPrint the usage line and exit 0.

Any other command prints Unknown command and the usage line to standard error, and exits 1. The three flags above are the only ones the CLI reads. A misspelled flag is ignored without a warning.

Usage

fossel init

Run it from the root of a repo. The output below is from a repo that already has an AGENTS.md, so init appends its hint there. It writes to rule files that already exist and never creates one. It looks for AGENTS.md, CLAUDE.md, .cursor/rules, .cursor/rules.md, .windsurfrules, .windsurf/rules.md, .clinerules and .rules. A marker comment makes the append idempotent.

Running it again changes nothing: no starter memory, no second hint.

The starter memory is added only when the entire database has no memories at all, not when only this repo has none.

fossel stats

Counts live, superseded and pinned memories, memories by type, memories that have never been returned by a context retrieval and were last updated more than 90 days ago (this count does not exclude pinned memories), memories whose referenced files have changed, the most common tags and entities, and the size of the database including its write-ahead log.

fossel doctor

Reports the repo key, the git remote and aliases, then checks for: sibling repo keys that look like the same repo, notes that still mention a deprecated key, exact-duplicate clusters, and whether a Cursor or Claude Desktop config file exists. It also prints counts of memories, stale memories, and how many have embeddings, entities and file references. It looks for ~/.cursor/mcp.json and Claude Desktop's config file only. Other clients are not checked.

When memories were saved under a bare folder name before the repo had a git remote, doctor flags them and exits 1:

--fix moves those memories under the canonical key, rewrites notes that mention the old key, and removes exact duplicates.

Environment variables

Fossel reads four variables and has no configuration file.

VariableDefaultEffect
FOSSEL_DB_PATH~/.fossel/memory.dbDatabase file. Missing parent folders are created. Read by the server and by every CLI command.
FOSSEL_WORKSPACEthe server's working directoryProject root used to find the repo, and the folder export_memories may write into. Read by the server only. CLI commands use the current directory.
FOSSEL_EMBEDDINGSoffSet to 1, true, on or yes (any case) to turn on hybrid search with vectors. Anything else leaves it off.
FOSSEL_EMBEDDER_CMDunsetA shell command that turns text into a vector, replacing the built-in embedder. Text goes in on standard input and a JSON array of numbers comes out on standard output. For many texts, Fossel sends one JSON-encoded string per line and expects one array per line. It runs with a 120-second timeout, and its output must be a numeric array. Changing the command makes Fossel re-embed every memory on the next search. This is the one place Fossel runs a command you configured.

Setting FOSSEL_EMBEDDER_CMD without FOSSEL_EMBEDDINGS does nothing for search. Embeddings are only used when the second variable is on.

Exit codes

CodeMeaning
0The command finished. doctor without --fix reported nothing wrong.
1An unknown command, doctor found a problem, or a command failed with an error. The server also exits 1 if it cannot start.
